# GlassMCP

Локальный MCP-сервер + панель управления в браузере: даёт ИИ-чату
(chat.co, Claude, ChatGPT, ZCode и др.) доступ к файлам и терминалу
твоего ПК. Кроссплатформенно: **macOS / Windows / Linux**.

**В систему ничего не ставится**: портативный Python лежит в `python/`,
зависимости — в `.venv/`, cloudflared — в `bin/`. Папку можно переносить.

---

## Быстрый старт

| ОС | Запуск | Остановка |
|---|---|---|
| **macOS** | `Start-MacOS.command` (двойной клик) или `./run.sh` | `Ctrl+C` в окне с сервером; для `--bg` — `./stop.sh` |
| **Linux** | `./Start-Linux.sh` или `./run.sh` | `Ctrl+C` в окне с сервером; для `--bg` — `./stop.sh` |
| **Windows** | `Start-Windows.bat` (двойной клик) | заверши процесс python в Диспетчере задач (pid — в `.server_pid`) |

По умолчанию сервер запускается **в этой же консоли**: логи идут в
терминал, а `Ctrl+C` аккуратно останавливает сервер и туннель.

Флаги: `--bg` — фоновый запуск (сервер живёт после закрытия терминала,
остановка только через `./stop.sh`), `--tunnel` — сразу поднять
туннель (адрес появится в панели). Флаг `--fg` оставлен для совместимости
и ничего не меняет — foreground теперь режим по умолчанию.

При первом запуске лаунчер сам скачает портативный Python (если нет
своего ≥3.10), поставит зависимости, сгенерирует токен и откроет панель:
**http://127.0.0.1:8090** (только с этого ПК).

## Панель управления

| Секция | Что делает |
|---|---|
| **Статус** | состояние сервера, MCP URL, кнопка перезапуска |
| **Туннель** | подключить/отключить Cloudflare quick-туннель (временный адрес для внешних клиентов), авто-проверка живости и кнопка «Проверить» |
| **Свой адрес (IP / домен)** | записать постоянный внешний адрес, если сервер доступен извне без туннеля — панель будет показывать его в «Подключении» |
| **Рабочая папка** | строгий режим: ИИ работает ТОЛЬКО в выбранной папке |
| **Настройки** | лимиты, таймауты, разрешённые/запрещённые пути, токен |
| **Зоны** | папки, подтверждённые для доступа в полном режиме |
| **Аудит** | журнал: какой инструмент что вызывал |
| **Логи сервера** | живой вывод сервера |
| **Подключение** | пошаговая помощь для chat.co / Claude / ChatGPT / ZCode |

## Режим рабочей папки (рекомендуется)

В секции «Рабочая папка» выбери папку → сервер перейдёт в строгий режим:

- **файлы**: любые операции строго внутри папки. `..`, абсолютные пути
  наружу и **симлинки, ведущие наружу** — отклоняются;
- **терминал**: команды выполняются внутри папки; ссылки на пути наружу
  в командах отклоняются (best-effort: shell не полностью изолировать —
  fs-инструменты строги всегда, shell-проверки эвристичны);
- зоны не используются — всё внутри папки разрешено, всё снаружи запрещено.

**Выбор папки обязателен.** При первом запуске панель открывает модальное
окно выбора рабочей папки (без выбора его не закрыть). Если выбранную папку
потом удалить или переименовать — доступ к файлам блокируется, сервер
продолжает работать, а окно выбора появляется снова. После первичной
настройки полный доступ можно включить осознанно — кнопкой «Отключить
(полный доступ)» в секции «Рабочая папка».

Без выбранной папки — режим полного доступа (как Claude Code): каждая
новая папка верхнего уровня требует подтверждения в чате (зоны).

## Как дать доступ извне: туннель vs свой IP/домен

| Способ | Что это | Когда удобен |
|---|---|---|
| **Cloudflare quick-туннель** | Бесплатная программа `cloudflared` сама соединяется с Cloudflare, и она отдаёт наружу временный адрес вида `https://случайные-слова.trycloudflare.com`. Ничего не надо открывать в роутере и заводить домен. | Быстро подключиться с телефона/другого ПК «здесь и сейчас». Адрес **меняется при каждом переподключении**. |
| **Свой IP** | У сервера есть постоянный публичный IP (или проброшен порт на роутере). Клиенты стучатся прямо на `http://1.2.3.4:8000`. | Когда адрес не должен меняться, а домена/хостинга нет. Минус: трафик идёт без HTTPS (без своего обратного прокси с сертификатом). |
| **Свой домен** | Имя `mcp.example.com` через DNS указывает на твой сервер (или на именованный Cloudflare-туннель, VPS, ngrok static и т.п.). | Постоянный красивый адрес + HTTPS. Требует настройки снаружи (DNS, сертификат, проброс/прокси). |

GlassMCP **не настраивает роутер и не выпускает сертификаты** — секция
панели «Свой адрес (IP / домен)» лишь **запоминает и показывает**
постоянный адрес, по которому ты сам сделал сервер доступным. Он
приоритетнее туннеля: пока задан, «Подключение» выдаёт клиентам его, а не
URL туннеля.

**Живость туннеля проверяется сама.** Пока туннель поднят, сервер каждые
30 секунд делает запрос `GET {url}/health` через Cloudflare. Если адрес
перестал отвечать (два сбоя подряд), статус меняется на красный
**«Туннель отвалился»** с причиной и кнопкой «Переподключить» — клиенты по
такому адресу не подключатся. Кнопка «Проверить» делает ту же проверку
вручную. Помни: quick-туннель выдаёт **новый адрес** при каждом
переподключении — обнови его в клиенте.

## Подключение клиентов

1. Выбери способ внешнего доступа:
   - **быстро**: в панели нажми **Подключить туннель** → получишь URL
     вида `https://что-то.trycloudflare.com` (меняется при каждом
     подключении);
   - **постоянно**: впиши свой IP/домен в секцию **«Свой адрес»** —
     панель начнёт показывать его как основной адрес подключения.
2. Адрес клиента = `<URL>/mcp`, авторизация — **Bearer**, токен из
   `.env` (показывается в панели, кнопка «Подсказка подключения»
   вставит готовые строки).
3. Пошагово для каждого клиента — в секции **Подключение** панели
   (вкладки: chat.co, Claude, ChatGPT, ZCode, Курсор и другие).
   Там же готовый JSON для ZCode/Cursor.

Если туннель не пробивается (ошибки 530/1033, «Could not resolve host»):
- включи **VPN** — в сетях, где режут Cloudflare/UDP, это лечит проблему;
- попробуй переподключить туннель (адрес будет новый);
- проверь `curl <URL>/health` — должен ответить `{"ok":true,...}`.

## Инструменты (22)

- файлы: `fs_list`, `fs_read`, `fs_write`, `fs_edit`, `fs_mkdir`, `fs_delete`
- поиск: `fs_glob`, `fs_grep`, `dir_tree`, `file_info`
- терминал: `shell_run`, `shell_run_async` + `shell_poll`, `shell_kill`
- расширения: `web_fetch`, `clipboard_read`, `clipboard_write`,
  `server_status`, `system_info`
- зоны: `approve_zone`, `list_zones`, `revoke_zone` (только в полном режиме)

## Безопасность

- Токен — в `.env` (`MCP_TOKEN=`). Кто знает токен — тот управляет ПК.
  Засветил — «Сгенерировать новый» в панели (клиенты переподключить).
- Панель доступна **только с этого ПК** (127.0.0.1); через туннель наружу
  смотрят лишь `/mcp` и `/health`.
- Свой адрес (`http://IP:порт`) — это прямой доступ без HTTPS: токен
  передаётся открытым текстом. Для постоянной эксплуатации ставь перед
  сервером обратный прокси с TLS (Caddy/nginx) или используй
  Cloudflare-туннель.
- Каждый вызов инструмента пишется в `audit.log` — видно, что реально
  делал агент.
- `fs_delete` не умеет рекурсию (защита от rm -rf); корень диска, дом,
  папка приложения и рабочая папка не удаляются никогда.
- История чата хранится в облаке клиента — не проси агент работать с
  чувствительными файлами.


## Известные ограничения

- Quick-туннель: адрес меняется при каждом подключении. Для постоянного
  адреса — секция «Свой адрес» (свой IP/домен, проброшенный порт, ngrok
  static или именованный Cloudflare-туннель).
- Shell-изоляция в режиме рабочей папки — best-effort (эвристика путей в
  командах); файловые инструменты изолированы строго.
- Windows/Linux-лаунчеры написаны и проверены по логике, но
  протестированы только на macOS (arm64) — на других ОС при первом
  запуске сообщай о проблемах.
- Если сервер запущен не лаунчером (вручную без перенаправления в
  logs/server.log), секция «Логи сервера» будет пустой.
